# AI Story Studio 衔接

本资源说明此 Skill 在创作室中的调用与交接，不改写其审查标准。独立使用时仍按 SKILL.md 的范围工作。

## 写后审查与修订

主创在完整场次、单集、本批或全稿写完后，保存正文并登记可用的原稿版本，自动委派独立审稿 Agent 使用本 Skill。传入 project_root、正文路径/ID/hash、实际完成范围、用户条件、项目格式和必要前后文。这里的自动是主创 Agent 的执行流程，不是后台监听器或未经验证的宿主 Hook。

已配置角色时使用 story-reviewer；否则使用宿主实际支持的独立子 Agent，并明确给出本 Skill 路径。没有子 Agent 能力时主创可按同一 Skill 审查，准确说明未进行独立审稿，不伪造调度。

- 审稿 Agent：只读正文、返回分级问题、建议和必要局部示例；报告保存于项目 outputs/script-review，绑定本次范围、正文版本/hash和稳定问题 ID。
- 写作 Agent：依据审查修订正文。用户已授权此写作流程中的修订，不为普通修法重复询问。会改变用户锁定条件的修法仍须取得对应选择，不能以过审为由重写核心。
- story-keeper：维护约束、原稿证据、伏笔与恢复索引；串行接收当前版本的报告与修订，不和审稿 Agent 并发写档案。不是审稿正文的修改者。

阻断、重大和确定的一般问题在授权范围内修复，建议项由主创结合创作目标决定是否采用。未提供材料或审美偏好不自动成为整改任务。保存修订稿并重新登记后，交审稿 Agent 复审旧问题和受影响上下文，守护 Agent 刷新相关证据。仍有明确问题就继续修订；遇到依赖用户选择或不可取得材料的阻断，说明实际缺口，不伪装通过。主创交付正文和必要修订说明，不要求用户阅读内部所有报告。

## 阶段与版本

本创作室交付终点是文学剧本；默认按文学阶段审剧情、人物、对白、可见动作、声音来源、连续性和时长。保留项目确认的中文格式。只在用户提供或要求制作稿时启用相应分镜、素材与 Seedance 能力审查，不因集成此 Skill 自动启动分镜或视频生成。

审稿通过不等于全项目定稿。终稿仍遵守现有守护 Agent、必回收伏笔、当前语义审查和结构审计闭环。当前请求只是单集时，审稿结论限于该集；连载未回收线索保持真实状态。

正文改变后旧报告只作历史，不能沿用旧版通过结论。压缩或恢复时读取最新正文、当前审查索引及待修问题，再继续修订；没有重新读到的范围不能声称已复审。
