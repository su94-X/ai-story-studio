# 与现有制作稿衔接

审查 Skill 独立工作，不依赖安装其他制作 Skill，也不自动改现有套件。先读当前项目的实际 schema/说明，再应用下面的映射。

## 采用稿与 source-speech-v2

有剧本、导演稿、采用稿多个来源时，以本次明确的采用规则审查，保留来源及差异。不可将作者示例、参考音频中的示范句或弃用稿当作当前对白。

有 source-speech-v2 时，核对原句、说话人、声音类型、源位置及逐句覆盖。长句拆成子句后检查 offset 覆盖、重叠/漏字和顺序；一条跨镜对白不是多个新增句。声音事件、voice_references、最终声音编号和实际音频数组应对应；没有外部音色参考的内联声线按本项目定义处理。

复核优先级：本次用户明确要求→当前采用稿/导演稿约定→源剧本。覆盖某个来源要有真实依据，不凭审查者偏好将导演稿静默改回剧本。

## scene-groups-v2 / v1

保留源场号、source_shot_id、source_segments、source_duration、生成组ID和 edit_window。一个源长镜分段时检查有序覆盖，一个组容纳多个短镜时检查顺序和剪入预算；不得将内部切镜自动视为独立付费目标。

旧 v1 的15秒或唯一镜号等规则只适用于其真实合同。v2 long_take 的较长路径，要检查项目要求的冻结能力证据与本次渠道限制；不能因目录名写着2.5就自行放宽。

场计划的实体 position/pose/gaze/held/contact/visibility 映射到连续性表，原字段保留。已有素材续组按父组实际选择与审核记录判断；没有观看证据就不标实际终态已验证。

## 提示词和参考

区分 author_prompt 与最终编译提交稿，最终稿包含的引用、声音及追加的连续性块都参与长度审查。作者文件名标签、接口 `[图片N]` 或 `@图片N` 语法依本次适配器，不跨渠道硬套。

某些本地套件曾采用最终稿2000 Unicode字符上限、普通4–15秒、条件长镜最多30秒等约定：只有当前项目仍明确采用且证据匹配时才适用；它们不是所有 Seedance 的通用上限。本审查不会修改这些配置。

审查时只读相关采用稿、场计划、公开能力与必要素材。不要遍历凭据、完整请求回执或用户未要求的历史项目。

## 旧 project.json

若结构含 characters、assets、segments、shots、utterances，可用结构助手。旧项目 `OS=内心独白` 必须以它自己的项目说明为映射来源；规范化审查视图保留 `speech_notation`，不要套给传统 O.S.。

其他 production manifest 不直接交给旧结构解析器。建立审查视图时只复制能对应的事实，在各段保留 `source_location`；未知的 duration、角色、声音或资产不编造。本视图不是执行器输入，不据此启动生成。
