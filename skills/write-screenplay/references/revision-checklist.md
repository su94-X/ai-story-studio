# 修订检查

完稿或收到修订任务时检查下列项目，直接修复授权范围内的问题。优先处理影响主冲突、可理解性和用户硬约束的缺口，再处理语言细节。

## 故事与因果

- 主角目标、行动期限和代价能否由剧情看出？
- 关键变化是否由已有行动、信息或规则导致？删去偶然救场和结尾才新增的万能能力。
- 人物能否采用明显更简单的办法？不能时给出可理解的阻力，不能只假定人物不会想到。
- 关键选择是否属于主角，后果是否可见？
- 结尾是否回应开场承诺和主问题？悲剧、反讽和开放结局也要有实际兑现。

## 人物与对白

- 每次转变是否有利益、证据、关系变化或行动铺垫？
- 角色知道的信息是否符合其实际见闻？
- 同一角色的价值取向、能力和限制是否一致，改变时是否有依据？
- 不看姓名能否区分主要人物的说话策略、词汇与节奏？
- 台词是否重复画面、解释双方都知道的背景，或替代本应发生的行动？

## 信息与连续性

- 设定的触发条件、边界、成本、例外是否前后一致？
- 时间线、出入场、地理关系、天气、服装、伤势和道具流转是否成立？
- 伏笔是否有铺垫与兑现，未兑现线索是否按计划保留在档案？
- 悬念、误导与反转是否依靠可追溯的信息，而非客观叙述造假？
- 来源事实、推断与创作虚构是否仍保持区分？修订是否添加了未核实事实？

## 形式与制作

- 每场能否写出人物目标、阻力、行动与新局面，或说明其必要功能？
- 动作、对白、声音和画面文字是否完整到足以理解事件顺序？
- 难场面的替代表现是否保留信息、压力和后果？
- 是否超过角色、场景、风格等已确认制作边界？超出时优先找保留核心的替代。
- 估算是否包含对白、动作、反应、文字阅读与留白？总时长是否匹配用户目标？

## 连续短剧补充

- 每集是否产生新局面、关系或信息，而非只延期同一个问题？
- 每集是否交付实际回报，并以结果创造下一集期待？
- 阶段结果是否落地，季终是否兑现全季主线？
- 是否保留持续冲突来源，同时避免无限加码和频繁重置人物？
- 全部请求集数是否完成？分批是否准确记录完成范围与剩余范围？

## 修订处理

| 问题类型 | 处理 |
|---|---|
| 错字、重复对白、未改变核心的逻辑缺口 | 直接修复，交付修订稿 |
| 场景超长或制作困难 | 压缩、重排或换表现，保持原戏剧作用 |
| 前文和后文冲突 | 以已确认设定与用户最新指令为准，修复并更新连续性档案 |
| 必须改变锁定核心才能解决 | 明确冲突与最小改动选项，推进不依赖选择的部分；不静默改核心 |
| 用户只要求点评 | 按严重性给出具体问题、位置及修复建议，不擅自改正文 |

给用户的修订摘要只说明实质变化、必要假设和仍需决定的事项。避免输出逐条自夸的检查通过清单，或把内部推理记录当成创作附件。
