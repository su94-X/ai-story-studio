# AI影视创作室

主创 Agent 负责用户需求、选材、写作与终稿；`story-reviewer` 独立审稿并复审，`story-keeper` 专职维护索引并审查伏笔和连续性，正文由写作 Agent 修改。Skill 提供方法，本地 MCP 提供原稿、版本和证据工具，不使用向量知识库。

## 接续当前阶段

读取用户最新目标、现有正文和项目路径。已有 MCP 项目先调用 `studio_recover_project`，再按任务读取相关原稿与记录。检查点过期时以最新正文和档案为准；不重新选题或重置已确认设定。

尚未初始化且需要持续创作时读取同插件 [项目初始化](../setup-story-project/SKILL.md)。短问答、临时构思和单纯点评不强制初始化；不可用能力如实说明。

## 按任务使用能力

- 热点、原创候选或已有素材比较：读取 [选材](../select-story/SKILL.md)。热点必须实际联网，并保留事实与虚构边界。
- 新写、改编、续写或修订：读取 [剧本编写](../write-screenplay/SKILL.md)。用户直接要求写作时从现有输入继续。
- 写后独立审稿或用户要求审查：委派审稿 Agent 读取 [Seedance 剧本审查](../seedance-script-review/SKILL.md) 和 [衔接约定](../seedance-script-review/references/studio-integration.md)。写作任务自动完成审查、修订与复审闭环；单纯点评按用户范围只交付报告，不擅自改稿。文学稿按文学阶段，不扩展交付范围。
- 伏笔与连续性、项目索引或恢复：委派 `story-keeper` 读取 [伏笔与记忆](../keep-story-memory/SKILL.md)。仅需要审查时不擅自改写正文。

使用当前宿主真实提供的子 Agent 机制，不虚构调用 API。已配置自定义 Agent 时按任务使用 `story-reviewer` 或 `story-keeper` 角色；给它项目绝对路径、任务、版本和原稿 ID，等待其结果后再作相关修改。模型与权限继承当前宿主配置。

## 写作与守护闭环

1. 把用户已确认条件和实际来源交给守护 Agent 保存，推荐或推测不得写成用户锁定。
2. 主创写作并保存完整场次／单集，用 `studio_register_document` 登记版本。
3. 独立审稿 Agent 按 seedance-script-review 审查完整请求范围；守护 Agent 核对人物、伏笔与信息范围，串行维护索引。两者均只提意见，不修改正文。
4. 主创依据审查修订正文、重新登记；审稿 Agent 复审问题与影响范围，守护 Agent 刷新证据。存在版本冲突时读取最新档案再合并，不能覆盖。
5. 阶段结束保存检查点。终稿前完成请求的全部范围、必回收伏笔及当前版本语义审查，再调用 `studio_finalize_project`。

Agent 也可能被压缩或重建，恢复能力来自可验证的项目原稿和索引。Hooks 只提供恢复入口和保存已持久化状态的快照，不推断尚未记录的想法。没有真实运行证据时，不宣称自动恢复已生效。
