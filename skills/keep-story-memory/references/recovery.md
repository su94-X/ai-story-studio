# 压缩与重新启动后的恢复

项目档案和原稿是依据。Agent 本身也可能被压缩或重建；另开一个 Agent 不能单独保证记忆持久化。

1. 确认 project_root 和 projectId。调用 studio_recover_project，不凭聊天中的候选序号猜项目。
2. 比较 checkpointCurrent、revision 和当前原稿 hash。检查点过期时仅用来寻找入口，不写回覆盖最新档案。
3. 先读取全部用户硬约束、当前任务、进度与相关索引，再按原稿 ID 阅读必要集/场。检查 recordPage/indexPage 的 nextOffset；索引和记录可分页，不把第一页误当全量。不要每次塞入全季所有材料。
4. 核对角色状态、各自知情范围、有效世界规则和待回收线索。发现正文未登记或旧证据时返回主创处理，不能默认所有记忆仍有效。
5. 向主创返回恢复出的具体处境、有效版本、待处理问题和下一步。恢复完成后再续写；不重新选题或重置故事。

SessionStart 的 compact/resume 等事件可以注入项目路径与恢复指令；PreCompact 只保存已经持久化的档案快照。Hooks 不会读取模型未输出的想法，不会在没有语义 Agent 的情况下自动判断记忆。

项目刚初始化、没有检查点时从原稿和空索引开始建立记录。v1 项目开发卡可读取并转换成记录，保留原件和迁移说明；原有卡缺字段不意味着剧情错误。

锁遗留、prepared 版本、不可读原稿或身份不一致时保留文件，说明具体问题。不要删除历史或盲目覆盖以继续。真正的自动 Hooks 恢复需要宿主支持、已审阅信任及实际运行证据。
