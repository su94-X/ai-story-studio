验证日期：2026-10-14。插件运行范围为本机 Codex、中文 AI 短片和连续短剧，终点为文学剧本。

## 可复现的检查

- Windows 本机 Node.js 24.16.0：32项 `node --test` 全部通过，无跳过。
- 五个 Skill 的 frontmatter、23个本地引用、共享交接资源和派生清单检查通过；skill-creator 的五次 quick_validate 通过。
- `plugin.json` 通过其声明的 agent-plugins.org 1.0.0 JSON Schema 校验。
- 官方 Python MCP SDK 1.29.1：协商协议2025-11-25，列出15工具，真实执行项目初始化与恢复。
- 自动测试包括原稿证据、过期引用、版本冲突、并发保护、历史稿、必回收项、语义复核、定稿、重启恢复和路径边界。独立试用发现的历史稿路径误标已修复并加入回归测试。
- 三次 Hook 事件输入模拟均成功恢复最新磁盘状态；它们单独不证明宿主已经自动调用 Hook。

## 本机 Codex 原生运行

使用已安装的 Codex CLI 0.157.1 app-server，在独立验证工作区开启临时会话；没有修改用户全局配置。项目 MCP 原生连接成功，并观察到真实子 Agent 的创建、守护 Skill 读取和项目恢复调用，未用 CLI 桥接替代原生工具。

补充读取子线程的宿主元数据，`agentRole` 和 `thread_spawn.agent_role` 均为 `story-keeper`，确认配置的专职角色实际加载；角色通过 MCP 读取 Skill 与参考，再恢复项目。

执行三次 `thread/compact/start`，每次均收到 `contextCompaction` 完成事件。随后模型真实调用 `studio_recover_project`，恢复出人物“林舟”、钥匙归还邻居、禁止死亡结局及门厅红线的下一场入口，四次验证对话均正常完成。测试档案保持 revision 1。这是已持久化内容的真实压缩恢复试验，不保证未记录内容或任何长稿永远不会失忆。

本次恢复由验证请求明确要求读取档案；Hooks 被解析且无错误，但仍是 `untrusted`，没有自动执行的运行回执。实际使用时需按宿主界面审阅并信任工作区与 Hooks。

初次使用 CLI 缓存的默认模型时，账号返回模型不可用；改用该测试账号可以运行的模型后完成试验。插件不锁定模型，也没有为解决测试问题修改全局默认值。

## 中文联网选材

按选材 Skill 实际检索中文近期公开网页，核对来源日期、合并同事件报道，制作5个虚构故事候选和3个深评。[完整示例](../examples/联网选材试用-20261014.md) 保留来源链接及读取范围。微博官方热榜访问受阻，没有冒充已取得官方排名。主创完成这一项试用，不把它描述为另一独立 Agent 的结果。

## 独立写作试用

独立主创使用实际 Skill，在隔离目录创作约3分钟短片《最后一格电》及6集连续短剧《四楼的水声》，另由守护 Agent 阅读正文并检查。传输为实际 stdio MCP 调用；该试用聊天自身没有绑定原生 MCP，不把 CLI 调用称作聊天原生工具。

短片经历三版正文修订，修正门缝空间、救援行动、人物知情及主角代价；守护者提交当前版本 pass 后真实定稿。必回收项保持 required，修改发生于正文和证据，不靠取消伏笔获得通过。[可读短片示例](../examples/原创短片-最后一格电.txt) 是合成虚构作品，非用户私人稿。

六集短剧经历三版正文修订，修正入室与注水的时间关系、人物对白来源、第三把钥匙的保管链及首夜没有及时止水的行动缺口。守护者逐集阅读357行、六集十场，重定位33条当前原稿锚点；七条必回收承诺均保持 required 并在真实正文兑现。提交 pass 后主创定稿至 revision 12，检查点有效、零失效证据、零待回收项。[完整六集示例](../examples/原创六集短剧-四楼的水声.txt) 随公开包提供。

一次 v2 复核中，结构 audit 已经通过，守护者仍提交 revise 指出首夜放任渗水的问题，促使主创修改正文；没有把结构通过替代语义判断。两部试写合计发现并修复七项正文问题。

运行过程中守护者两次流中断，新的守护 Agent 从落盘版本、正文和17条索引恢复，识别过期检查点并继续复核。该事件证明中断后的档案可供重建 Agent 使用，不等于自动 Hook 已运行。
